0. 一分钟读懂

  • 这是什么：Windows 桌面自动化工具。输入一份导出清单（CSV：衣物条码 + 照片文件夹路径），它自动操作门店管理软件「洗衣管家」，把每个订单对应的照片批量上传，并输出执行结果。
  • 技术栈：Python 3.14 + Tkinter(GUI) + PyAutoGUI + Chrome DevTools Protocol（WebSocket）+ Win32 消息/窗口 API。
  • 两种运行模式： 1. CDP 精准模式（首选）：通过洗衣管家的 Chromium 调试端口（9222）做页面级控制； 2. 图像锚点/坐标模式（兜底）：截图模板匹配 + 坐标点击（调试端口不可用时自动切换）。
  • 最重要的一条经验（务必先读 §4.3）：洗衣管家以管理员权限运行，本工具也必须以管理员权限运行（打包参数 --uac-admin）。权限不同级时，Windows 会静默拦截所有自动化操作——这是本项目踩过最深的坑。

1. 业务背景与目标

1.1 背景

  • 目标软件「洗衣管家」（xygjwinapp.exe）：洗衣门店使用的 Windows 桌面管理系统，本体基于 CefSharp（Chromium 内核），程序目录 D:\Blending_Release-6.1.17\。
  • 日常痛点：每收一件衣物需要为其上传照片。在软件「拍照页」的手工流程为： 输入条码 → 查询订单 → 点击【上传图片】→ 在系统文件框里进入该订单的照片文件夹 → 全选 → 确认。 一批订单几十件，重复劳动强度大。
  • 解决方案：按《导出清单》格式批量自动执行上述流程。

1.2 输入 / 输出

  • 输入：导出清单 CSV（编码兼容 GBK / UTF-8，程序自动识别），列包含： 条码、照片数量、文件夹位置（如 E:\收衣照片\110000044440）。
  • 输出：输出结果\ 目录下生成 执行结果_时间戳.csv/.xlsx（含每条状态）、运行日志_时间戳.txt、出错时现场截图（出错截图\）。

1.3 核心业务规则

  • 防重复上传：执行前检查订单在软件中已有的照片数；已有照片的订单默认跳过（options.skip_if_has_photos=true）。
  • 部分完成处理：上传未达预期张数时，标记“疑似部分完成 N/M 张，请人工核对”，不盲目重传（避免重复）；分批逻辑可精确定位缺失批次，便于补传。
  • 按订单文件夹整批上传：一个订单一个照片文件夹。

2.2 单条订单的完整流程（CDP 精准模式）

[1] 连接调试端口 9222：HTTP GET /json 找到页面 target → WebSocket 连接
[2] 导航到拍照页（路由：#/clothManage/photograph?...）
[3] DOM 级输入条码（native setter + input/change 事件）→ 点击「查询/确认」
[4] 等订单数据刷新（页面出现该条码）→ 统计已有照片数（OSS 图源去重计数）
      ├─ 已有照片（≥ 本地张数）→ 跳过（防重复）
      └─ 否则进入上传
[5] 上传阶段（每批约 5 张，见 §4.2 分批）：
      a. 自动把洗衣管家窗口置前 + 置顶（上传完成后还原）
      b. CDP 受信任点击【上传图片】→ 系统「选择图片」对话框打开
      c. 选择文件（首选"消息通道"：WM_SETTEXT 写文件名框 + BM_CLICK 点"打开"；
         备用：键盘/剪贴板；最后：导航文件夹+全选）
      d. 等对话框关闭 → 轮询页面照片数增加 → 达到预期张数才算成功
[6] 记录结果 → 下一条

2.3 可靠性设计（多层兜底）

  1. 对话框选择：消息通道（最稳）→ 键盘+剪贴板（带双重校验）→ 文件夹导航+全选（最后手段）；
  2. 打开对话框：CDP 受信任点击（重试 3 次）→ 真实鼠标点击（重试 2 次）；
  3. 整轮回退：一批选择失败会关闭对话框重开重试一次；
  4. 失败不假成功：以"页面照片数实际增加"为最终验收标准。

4. 技术要点与深坑（重点！）

记录"为什么这样做"与"哪些路走不通"，改代码前务必通读。

4.1 CDP 精准模式（洗衣管家是 CefSharp 应用）

  • 启用方式：软件带参数启动 --remote-debugging-port=9222（本机桌面快捷方式已自带）。
  • 连接：http://127.0.0.1:9222/json 取 target → WebSocket 地址 → Runtime.evaluate / Input.* / DOM.* 可用。
  • 页面路由：首页 #/、更多页 #/more?id=9、拍照页 #/clothManage/photograph?moduleid=3&templetid=3007&layoutType=1。
  • 页面关键元素：
  • 「上传图片」按钮：p.upload_btn（注意：按钮含一个图标子节点，"叶子文本"式查找会找不到，用选择器）；
  • 照片区：.photo_content、缩略图列表 .pict_list li；
  • 条码输入框：input[placeholder*="衣物条码号"]，查询按钮 p.search_btn；
  • 照片计数：页面 img 的 OSS 图源去重计数（uploaded_photo_count()）。
  • 重要教训： 1. 点击【上传图片】必须用"受信任点击"：Input.dispatchMouseEvent（moved→pressed→released）。普通 JS element.click() 打不开系统文件框（浏览器要求用户手势）。 2. 受信任点击要 fire-and-forget：对话框一旦打开，渲染进程会被阻塞，后续 CDP 调用全部超时——点击事件发出后不要等响应。 3. 对话框打开期间禁止一切 CDP 调用（会超时并可能损伤连接）。对话框阶段全部走 Win32 API + PyAutoGUI。 4. "注入文件"路线已废弃：向 .photo_content 的隐藏 input[type=file] 注入文件（DOM.setFileInputFiles）不会触发组件上传（文件塞得进、界面无反应）。不要重走。

4.2 系统「选择图片」对话框自动化（核心难点）

  • 对话框特征：类名 #32770，标题「选择图片」；内容为 DirectUI 样式。
  • 控件定位（EnumChildWindows 枚举后代）：
  • 文件名框 = 位于对话框下半部（y > 60% 高度）的最宽 Edit 控件（地址栏 Edit 在上半部分，据此排除）；
  • 「打开」按钮 = 类名 Button、文本含「打开」的真实 Win32 按钮（可发消息点击）。
  • 首选通道：消息直写（最可靠、不依赖焦点/键盘）： SendMessage(文件名框Edit, WM_SETTEXT, 0, "带引号的多文件全路径") SendMessage(打开按钮, BM_CLICK) # 或 SendMessage(对话框, WM_COMMAND, 1, 0) 写入后用 SendMessageW(edit, WM_GETTEXT, ...) 直读控件内容校验，通过才点"打开"。
  • 备用通道：键盘/剪贴板（要求对话框在前台）：
  • 置前：AttachThreadInput 技巧（直接 SetForegroundWindow 在高负载环境常失败）；
  • 粘贴后用「清空剪贴板 → Ctrl+A/Ctrl+C → 读回」校验（⚠️ 必须先清空，否则"复制失败"时会读到残留内容 → 假成功）；
  • 多轮：直接粘贴 → 点击文件名框再粘贴 → Alt+N 聚焦再粘贴。
  • ⚠️ 文件名框有长度上限（实测 259 字符）：带引号的多文件全路径串过长会被截断，末尾文件变无效路径。必须分批：_chunk_files_by_length() 控制每批 ≤240 字符（约 5 张/批），逐批重复整个对话框流程。（实测 13 张 → 分 3 批全部成功。）
  • 最后手段：导航文件夹（粘贴文件夹路径→回车）→ 点列表空白 → Ctrl+A → 回车。

4.3 ⭐ 权限级别（UIPI）——全项目最深的坑

  • 现象：对话框弹出后，"写内容/粘贴/回车"全部无效，界面一直停着。日志显示"校验成功"但框里仍是空的（假成功）。
  • 根因：洗衣管家程序清单强制以管理员权限运行；旧版工具是普通权限。Windows 的 UIPI（User Interface Privilege Isolation） 会静默拦截低权限进程对高权限窗口的 SendMessage、键盘输入、剪贴板注入——不报错、直接丢弃。
  • 排查方法：对比进程"完整性级别"（Integrity Level：S-1-16-8192=普通 / S-1-16-12288=管理员），OpenProcessToken + TokenIntegrityLevel 读取（参考 main.py._proc_il_value()）。
  • 正确解法（v1.6 起）：工具也以管理员启动——PyInstaller 打包加 --uac-admin（嵌入 requireAdministrator 清单）。
  • 本机 UAC 为"不提示直接提升"（ConsentPromptBehaviorAdmin=0），双击无弹窗、用户无感；
  • 换机器部署注意目标机 UAC 设置：标准 UAC 下会弹一次"是否允许"，属正常现象（目标软件本身也需管理员）。
  • 教训：所有"粘贴不进去/消息无反应"类问题，先查权限级别，再查代码。

4.4 调试模式自动保障（每次运行前）

  • 执行前自动检查 9222 端口；不可用时按需处理： 1. 软件未启动 → 自动 Popen([exe, "--remote-debugging-port=9222"]) + 等端口就绪； 2. 软件开着但无调试参数 → 确认后自动重启（正常关闭 → 6 秒未退出自动 taskkill /F → 带参重启，最多两次尝试）。
  • 实现要点：等待期间用事件泵刷新界面（防"卡死"观感）；tasklist/taskkill 子进程调用加 CREATE_NO_WINDOW（防黑窗）。
  • 启动洗衣管家-调试模式.bat 可手动以调试模式拉起软件。

4.5 其它已踩的坑（速查）

  • 窗口匹配：pygetwindow.getWindowsWithTitle('洗衣管家') 会把工具自身窗口也匹配进来（标题包含关系）；用 winmatch.pick_best_window() 打分选（完全相等 > 开头 > 包含；排除工具/浏览器后缀）。
  • GitHub Release 附件名只支持 ASCII：中文名会被服务端打碎成点号（实测）；安装包附件用英文名（Xiyiguanjia-Uploader-Setup-vX.Y.exe），中文显示名放附件 label 字段。
  • 火绒安全软件：会把含 taskkill+schtasks 特征的脚本文件当恶意行为直接删除；此类系统操作尽量用直接命令执行，或给目录加白名单。
  • PowerShell 中文陷阱：中文传给内联脚本/命令行易乱码——一律用 .py 脚本文件 + UTF-8；写中文文件用 utf-8-sig。
  • 页面指纹顺序：图像兜底模式页面识别优先 _b 变体（规避界面遮挡）。
  • 照片计数时序：换订单后等"条码信息刷新 + 连续两次读数一致"再采纳（防读到上一单残留）。
  • 升级安装：安装器替换 exe 前先关闭运行中的工具（文件占用）。

5. 构建与发布流程

打包脚本已归档在 构建工具/（含 README.md、ChineseSimplified.isl、manual_template.html）。换机器或移动项目目录后，先按 构建工具/README.md 修改脚本顶部的路径变量（脚本内保留开发机绝对路径）。

5.1 打包链（4 步）

步骤 脚本 产物
1 build_app.py（PyInstaller：--windowed --uac-admin + hidden imports） pkg/dist/洗衣管家上传助手/（onedir）
2 assemble_payload.py dist 内补入 assets/anchors/config/文档/bat
3 build_installer.py（Inno Setup + 中文语言包） 洗衣管家上传助手_安装包_v{版本}.exe
4 （可选）build_manual.py 程序说明.html（模板 + 截图 base64 内嵌）

5.2 版本与发布约定

  • 版本号：main.py 的 VERSION；同步更新 CHANGELOG.md、README.md、程序说明.html；
  • Git 提交并推送 origin main；
  • GitHub Release：正文=版本更新日志；附件=安装包（ASCII 名 + 中文 label）；v1.2 起每版均有 Release；
  • .gitignore：输出结果/、运行日志_*.txt、__pycache__/、.openclaw/（运行时产物与门店数据不入库）。

5.3 安装策略

  • 装到 %LOCALAPPDATA%\Programs\洗衣管家上传助手（当前用户，安装免管理员）；自动创建桌面/开始菜单快捷方式；unins000.exe 卸载；
  • ⚠️ 程序本体启动需要管理员（--uac-admin，为匹配洗衣管家权限，见 §4.3）。

8. 已知限制与后续建议

  1. 依赖洗衣管家版本：若软件大版本升级，页面路由/元素选择器可能变化——优先更新 cdp_control.py 中的路由与选择器；图像模式的页面指纹（anchors/）也需重新截取。
  2. 管理员权限为硬要求（双方都要）；换机部署注意 UAC 提示。
  3. 图像兜底模式需先做坐标校准（CDP 模式无需）；分辨率/缩放变化会影响图像模式。
  4. 单机单实例假设；未实现多店并发/排队。
  5. 数据质量：条码错误时软件提示"衣物详情不存在"，工具标记失败属正常（清单数据需与系统一致）。
  6. 建议增强（按需）：结果推送到企业微信/飞书；定时任务；把 Releases 作为唯一分发渠道（仓库内不再放 exe，避免膨胀）。

10. 快速上手（接手后的第一次运行）

  1. 打开「洗衣管家」（桌面快捷方式；或开工具后由工具自动拉起）；
  2. 以管理员身份打开「洗衣管家上传助手」（双击即可；本机 UAC 静默、无弹窗）；
  3. 点【导入清单文件…】选择 CSV（如 E:\桌面\新建文件夹\导出清单_*.csv）；
  4. 先点【测试第一条】观察全流程（或勾选【演练模式】只预检不上传）；
  5. 确认无误 →【▶ 开始执行】；结果到 输出结果\ 查看。
